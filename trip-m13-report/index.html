Defect 1 — measuring the walk makes the tool worse

chongqing · 42 directed pairs · reproducible by ablation

Why it only goes one way here

        

          ride is identical in both runs, so a reverse flip would
          need measuring to shorten a walk. That is possible in
          principle — the model walks at 4.5 km/h with a 1.3 detour factor,
          about 3.46 km/h over the geodesic, which a real router can beat. It
          just never happens in Chongqing, the most vertically extreme city this
          tool has touched:
        


        

          

            
              
measured walk vs modelledpairsdelta

            
            
              
longer40 / 42median +9 min

              
shorter0 / 42max +32 min

              
equal2 / 42min 0

            
          

        

        

          So the direction follows from the model being wrong in this city, not
          from geometry. In a flat grid city the flips could go the other way.
          What is structural is that the two sides of the comparison
          have different bases.
        


        
The mechanism

        
// src/plan/travel.ts:121
const ride = walkMinutesForKm(r.accessKm)   // modelled
           + BOARDING_MINUTES               // assumed
           + r.rideMinutes
           + walkMinutesForKm(r.egressKm);  // modelled

// src/plan/travel.ts:136
walkWins: w.minutes <= ride                 // w is MEASURED


        

          

            M12 left the same-station case to fall out of line 136
            deliberately, and said why at travel.ts:129–132: "a zero-stop ride still costs boarding." That
            reasoning is what this run falsifies. A zero-stop ride costs
            boarding plus two modelled access walks, and against a
            measured direct walk that sum can come in lower.
          

        


        
It contradicts the M12 recon

        

          Finding 3 of that recon called the same-station case structurally
          safe. It holds only when nothing is measured — and the recon ran with
          no route_legs present, while trip route is a
          documented step users are told to run. The recon measured the one
          configuration in which its own claim is guaranteed true. That is the
          M6 rule in its M12 form: the recon's setup is one of the things that
          can be wrong.
        

        

          Note the 42 pairs here come from the seven places the video
          named, not from M9's Chongqing set. No same-set comparison is claimed
          — the recon's statement was general, so one counterexample is enough.
        


        
Two fixes, and one is blocked

        

          

            
what it iscost

            
              

                a
                The comparison is mixed-basis — measured against modelled.
                Route segment→station legs. Network + schema.
              

              

                b
                A same-station "route" is not a route at all.
                Blocked — see below.
              

            
          

        

        

          The one-line version of (b) is to return null for a
          same-station route. That breaks reach() in
          src/commands/transit.ts, which asks proximity by
          routing a point to itself and depends on that branch returning
          non-null. Which is what makes it a milestone rather than a guard.

Why the suite is green

        

          walkWins appears in one test file,
          test/travel-transit.test.ts. No export test ever
          constructs a walk-wins hop, and no test constructs a same-station pair
          with measured legs present. Both defects live in the gap between two
          things that are each tested alone.
